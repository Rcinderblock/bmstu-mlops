# ДЗ4 — четыре дефекта подготовки последовательностей

Проверено на русских командах личного планировщика: 2743 строки train и 352 val.
Исходная заготовка запущена отдельно на тех же файлах; измерения сохранены
в [hw04-starter-probe.json](results/hw04-starter-probe.json). Тест преподавателя
`tests/check.sh` скопирован без изменений, SHA-256 начинается с **f2002c8c9519**.
Обучение модели не запускалось: проверяется подготовка данных.

## 1. В ошибку обучения попадал весь промпт

Причина: `mask_prompt` возвращала копию `input_ids`, а граница ответа всегда
равнялась нулю. Модель получала цель воспроизводить инструкцию и вопрос,
хотя задача — выдавать только метку действия. Симптом из условия — повторение
вопроса — ожидаемое следствие такой цели; обучение с этим дефектом здесь
не проводилось и наблюдаемое поведение модели не приписывается эксперименту.

Исправление в `src/tokenize_data.py`: полный текст остаётся во входе, но
`labels` до ответа равны `-100`. Пустой блок рассуждений также входит в промпт.
Ответ и завершающий EOS участвуют в ошибке, перевод строки после EOS исключён.
Сдвиг целей оставлен функции потерь модели. Граница сначала проверяется
по токенам, при склейке используется карта соответствия символам. Токен,
который пересекает границу, целиком маскируется.

Числа: исходник давал **415065 из 415065** обучающих позиций. Исправленный
шаблон содержит **426037** входных токенов, из них цели — **8553 (2.01%)**.
Разные размеры входа объясняются также исправлением шаблона в пункте 2.
Проверка преподавателя декодирует цели всех **2743** примеров и сверяет ответы.
Тест со словом «Приве» / «Привет, мир» принудительно проверяет склейку;
на обычных диалогах запасной путь понадобился **0** раз.

## 2. Обучение и генерация использовали разные шаблоны

Причина: полный диалог собирался вручную строками ролей, а промпт генерации —
штатным шаблоном. При Qwen3 в промпте появляется пустой блок рассуждений,
которого не было в самодельной строке. Поэтому обучение и генерация видели
разное начало ответа. Простое переключение `enable_thinking` на true
не решает задачу: служебный блок может попасть в обучающие цели.

Исправление: единственный вызов `apply_chat_template` находится в
`src/prompt.py`. Оба пути используют один `model.enable_thinking=false`.
Существующая генерация через `src/model.py` также вызывает этот модуль.
Служебные строки ролей не прописываются в исходниках. Стадия проверяет
побайтовое совпадение префикса до маскирования каждого примера.

Числа: в исходнике совпало **0/352** префиксов val, после исправления —
**352/352**, дополнительно **2743/2743** в train. Тест подменяет шаблон
на намеренно несовпадающий и подтверждает остановку до записи неверной маски.

## 3. Короткие строки дополнялись справа

Причина: настройка `padding_side` не применялась к токенизатору,
а коллатор по умолчанию дополнял справа. При пакетной генерации decoder-only
модели выбирают продолжение по последней позиции, где у короткой строки
в таком случае оказывается заполнитель. Это объясняет различие между
одиночной генерацией и батчем из строк разной длины.

Исправление: настройка из `params.yaml` применяется при подготовке и загрузке
токенизатора. `DynamicPaddingCollator` по умолчанию добавляет позиции слева
до максимальной длины внутри конкретного батча: входу — pad, маске внимания —
0, целям — `-100`. Контекст по-прежнему доступен вниманию, а заполнение — нет.

Числа: первый настоящий батч имеет форму **8 × 160**, исходные длины строк —
155, 150, 160, 154, 150, 156, 148, 146. Динамические заполнители занимают
**5.74%** позиций train против **30.66%** при постоянной длине 224.
Неверных целей на заполнителях — **0**. Отдельный тест на длинах 2 и 4
проверяет точное расположение всех трёх массивов, а не только настройку.

## 4. Обрезка не попадала в отчёт

Причина: `truncation_stats` возвращала пустой словарь. Нельзя было понять,
сколько последовательностей потеряло конец ответа. Если считать долю только
после удаления примеров без ответа, исчезнувшие длинные строки занизят оценку.

Исправление: длина измеряется до обрезки для каждой входной записи.
Отдельно считаются число и доля обрезанных, оставшиеся обучающие позиции
и удалённые примеры. Превышение порога **5%** или пустая выборка завершают
стадию с ошибкой, диагностический отчёт сохраняется. В `dvc.yaml` указаны
входные файлы, код, настройки и все выходы, включая автоматически создаваемый
`docs/tokenize_report.md`.

Числа: p99 train — **175**, максимум — **193**; val — **173** и **185**.
Выбран предел **224**, ближайшее кратное 32 выше измеренного максимума.
Обрезано **0/2743** и **0/352**, удалено без ответа **0**. На этих коротких
командах исходные 232 тоже достаточны; цифры обрезки из лекции сюда не переносились.

Контрольный запуск `uv run --locked python scripts/probe_tokenization.py`
с лимитом 160 получил **552/2743 (20.12%)** и **75/352 (21.31%)** обрезанных;
без обучающих позиций осталось **314** и **49** примеров. Порог отмечен как
нарушенный в [hw04-short-limit.json](results/hw04-short-limit.json).
Этот эксперимент не меняет основные настройки и сохранённые последовательности.
