# Паспорт данных: русские команды личного планировщика

## Задача и источник

По русской команде выбрать одно из девяти действий: создать, посмотреть или
удалить будильник, событие календаря, список или пункт списка. Это классификация
намерений. Модель в этой работе не обучалась; качество распознавания не измерялось.

Источник: [MASSIVE 1.0](https://github.com/alexa/massive), Amazon, локаль `ru-RU`,
16 521 запись, из них 3713 относятся к calendar/lists/alarm. Источник основан на
[SLURP](https://arxiv.org/abs/2011.13205), [статья MASSIVE](https://arxiv.org/abs/2204.08582).
Лицензия данных: CC BY 4.0, полная копия в `docs/MASSIVE-LICENSE.txt`.
Все исходные тексты принадлежат их авторам; здесь выполнены отбор, фильтрация,
добавление инструкций, групп и новое разбиение. Адрес архива и SHA-256 архива
и русского файла зафиксированы в `conf/source.json`.

Тема выбрана для проекта по поручению пользователя. Согласование преподавателем
и уникальность темы в потоке не подтверждены.

## Переработка источника

Из 18 исходных областей оставлены три связанные области личного планировщика.
Метка должна принадлежать разрешённым девяти действиям и соответствовать области.
Нужно минимум два голоса разметчиков за верное намерение и русский язык.
Текст с удалённой разметкой слотов должен совпасть с исходной командой.
Одинаковые нормализованные команды с противоречивыми метками исключены целиком
по реестру всего зафиксированного источника, одинаковому для обеих версий.
Команды со словом «таймер» исключены: отдельного действия таймера в задаче нет.

| Шаг v2 | Строк |
|---|---:|
| Русский источник | 16521 |
| За пределами выбранных областей | 12808 |
| В выбранных областях | 3713 |
| Исключены таймеры | 3 |
| Не набрали два голоса | 129 |
| Противоречивые метки | 5 |
| Неизвестная метка / несогласованная разметка слотов | 0 / 0 |
| Записано в raw.jsonl | 3576 |
| Отброшено по длине | 0 |
| Удалено точных / близких повторов | 120 / 1 |
| Осталось в clean.jsonl | 3455 |

Счётчики последовательные и не суммируют одну строку несколько раз.
Проверка агентом 27 примеров (по три на класс, seed=42) выявила один таймер
с меткой календаря; это послужило основанием явного фильтра. Проверка
противоречий выполнялась по всему корпусу. Полная экспертная переразметка
не проводилась: два голоса источника не гарантируют семантическую правильность.

## Формат и очистка

UTF-8, JSONL, поля `id`, `topic`, `messages`. Роли строго `system`, `user`,
`assistant`, именно в таком порядке. Пользовательская часть — исходная команда,
ответ — метка действия. Четыре варианта общей инструкции распределены
детерминированно по исходному id. Верная метка не подставляется в запрос.

`topic` хранит ключ группы шаблона. В `annot_utt` значения слотов заменяются
их типами; каркас нормализуется и сокращается SHA-256. Запросы с одинаковой
конструкцией и разным временем/названием события остаются вместе. Метка класса
не используется в ключе группы, поэтому разные действия могут встречаться
в одной выборке без превращения каждого класса в отдельную выборку.

Порядок очистки: полная проверка схемы → длина → маскировка → точные повторы
нормализованного запроса → близкие повторы. Диапазон длины запроса 5–500 символов
сохраняет короткие команды. Ответ не короче двух символов. Регистр, пробелы,
совместимые символы Unicode и тире нормализуются для сравнения.

MinHash ищет кандидатов по четырёхсловным шинглам, 64 перестановки, seed=42.
Точный Жаккар ≥ 0.85 подтверждает совпадение. Обратный индекс общих шинглов
добавляет пропущенных вероятностным поиском кандидатов; результат проверен
против полного перебора в тесте. Для коротких строк шингл — вся последовательность
слов. Сохраняется первый представитель; порядок train/dev/test и id фиксирован.

Телефон, email и явно отмеченная дата рождения маскируются во всех ролях.
На реальном наборе найдено 0 совпадений; контрольный тест находит все 3.
Имена, адреса и прочие персональные сведения этими шаблонами полностью
не покрываются. Обычные даты событий намеренно сохраняются.

## Разделение и утечки

Целая нормализованная группа получает выборку по SHA-256 от seed=42 и её ключа.
Доли заданы 80/10/10, фактические размеры могут немного отличаться: группы
не разрезаются. Прежние группы не меняют выборку при расширении версии.

| Выборка v2 | Строк | Групп | Доля |
|---|---:|---:|---:|
| train — обучение | 2743 | 2629 | 79.39% |
| val — настройка | 352 | 331 | 10.19% |
| test — итоговая проверка | 360 | 330 | 10.42% |

Во всех трёх выборках присутствуют все девять классов. Отдельная стадия после
сохранения файлов проверяет train/val, train/test и val/test. В каждой паре
0 пересечений по id, текстам, группам и близким текстам. Порог Жаккара одинаков
в очистке и проверке; несовпадение порогов вызывает ошибку. Ненулевое пересечение
тоже завершает стадию ошибкой. Результат — `metrics/contamination.json`.

Группировка контролирует одинаковые каркасы и лексическое сходство, но не
распознаёт все смысловые парафразы. Этот результат не доказывает отсутствия
любой семантической утечки.

## Разнообразие и длины

| Показатель v2 | Результат | Порог |
|---|---:|---:|
| Примеры после очистки | 3455 | ≥ 1000 |
| Варианты инструкции | 4 | ≥ 3 |
| Группы шаблонов | 3290 | ≥ 50 |
| Доля крупнейшей группы | 0.35% | ≤ 10% |
| Классы | 9 | ≥ 9 |
| Доля крупнейшего класса | 31.90% | ≤ 40% |
| Уникальные нормализованные запросы | 100% | 100% |
| p90/p10 длины запроса | 3.05 | ≥ 2 |

Класс — короткая фиксированная метка: 99.74% ответов повторяют уже встреченный
ответ, самая частая длина занимает 41.16%, p90/p10 ответа=1.36. Поэтому ограничения
на эти три величины заменены контролем разнообразия запросов и классов:
`min_answer_len_ratio=1`, `max_same_length_share=1`,
`max_duplicate_answer_share=1`. Это осознанное исключение для классификации,
а не доказательство разнообразия на основании четырёх инструкций.
Большинство каркасов одиночные; число групп само по себе не означает 3290
разных смысловых задач. Дополнительно контролируются распределение классов
и длины входов. Полные распределения классов есть в `metrics/split.json`.

| Длина в символах | min | p10 | p50 | p90 | p99 | max |
|---|---:|---:|---:|---:|---:|---:|
| Запрос | 5 | 22 | 40 | 67 | 100 | 148 |
| Ответ-метка | 9 | 11 | 12 | 15 | 17 | 17 |

Стадия разнообразия — обязательное условие продолжения: нарушение любого
порога записывается в метрики и завершает процесс ошибкой. Набор из 1200 строк
с одной инструкцией и одной группой отвергается, независимо от объёма.

## Хранение и воспроизведение

Данные находятся только в `data/` и хранилище DVC. Git хранит код, настройки,
контрольные суммы, метрики и отчёты. `source.dvc` описывает исходные файлы;
`dvc.yaml` задаёт зависимости, а `dvc.lock` связывает версии входов и результатов.
Локальное хранилище — `../MLOps-dvc-store`, данные обеих версий отправлены туда.

На другом компьютере: `make install`, `make fetch-data`, `make data`.
Доступ к моему локальному хранилищу не нужен: источник скачивается с проверкой
SHA-256. Восстановление только из хранилища: `uv run --locked dvc pull`.
Смена версии: `uv run --locked python scripts/set_version.py v1` и `make data`.
Далее аналогично v2. Воспроизведение проверяется по содержимому файлов,
а не только по успешному коду завершения команды.

## Ограничения и назначение

Переведённые команды голосовому помощнику не равны реальным обращениям в
приложение. Есть ошибки перевода, неоднозначные формулировки и запросы,
которым нужен контекст. Новое разбиение не является официальным тестом MASSIVE.
Дисбаланс классов сохранён, никакого выравнивания повторами нет.
Это учебные данные для будущего обучения классификации, а не проверенный
производственный помощник. Контент не отправляется реальным календарям.
