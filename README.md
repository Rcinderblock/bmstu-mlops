# MLOps: учебный проект

Один проект на весь семестр. ДЗ1 — запуск языковой модели и измерение скорости.
ДЗ2 — устройство модели, параметры LoRA, активации и память при обучении.

## Запуск

Нужны `uv` и Python 3.12. Команды выполняются из корня репозитория:

```sh
make install        # точные версии из uv.lock
make inspect        # расчёты ДЗ2 и новый отчёт
make check          # семь проверок ДЗ2, с реальными прогонами модели
make test           # десять небольших тестов измерений и исправлений
```

Модель при первом запуске скачивается с Hugging Face. После скачивания:

```sh
HF_HUB_OFFLINE=1 make inspect
HF_HUB_OFFLINE=1 make check
```

## Результат ДЗ2

Qwen/Qwen3-0.6B, Apple M3, `mps`, `bfloat16`, 256 токенов, batch=1.
Один прогон каждого режима в отдельном процессе, один шаг обучения AdamW.

- Уникальных параметров: **596 049 920**. Сумма групп совпадает с прямым подсчётом.
- LoRA r=8 на q/v: **1 146 880** параметров; r=16 на семи проекциях: **10 092 544**.
  Оба расчёта совпали с `peft`.
- Пик памяти драйвера: **2197,6 МиБ** без обучения, **3579,6 МиБ** с LoRA,
  **6083,6 МиБ** при полном обучении.
- Семь проверок ДЗ2 и десять небольших тестов пройдены.

Подробности и ограничения измерений — в [отчёте](docs/anatomy.md).
Память MPS измерена опросом `torch.mps.driver_allocated_memory` во время вычислений;
короткий пик между опросами может быть пропущен. Это не RSS процесса и не оценка качества обучения.

## Где что находится

| Файл | Что делает или содержит |
|---|---|
| `params.yaml` | Модель, устройство, запросы, длина входа и две конфигурации LoRA |
| `pyproject.toml`, `uv.lock` | Прямые зависимости и полный набор точных версий |
| `src/model.py`, `src/config.py` | Общая загрузка модели и настроек |
| `src/inspect_model.py` | Подсчёт параметров, наблюдение за слоями, процессы измерения памяти |
| `src/report.py` | Сборка таблиц и графика отчёта |
| `docs/anatomy.md` | Объяснение результатов и исправлений ДЗ2 |
| `docs/report.json` | Числа, имена и размеры всех тензоров, условия и история пиков |
| `docs/activations.png` | График норм на выходе первого, среднего и последнего блоков |
| `docs/anatomy-worksheet.xlsx` | Заполненная таблица преподавателя с формулами и ответами |
| `tests/check.sh` | Семь проверок ДЗ2 |
| `tests/test_inspect_model.py` | Общие веса, снятие хуков при ошибке, пик памяти и формула LoRA |
| `docs/results/` | Сохранённые протоколы проверок |
| `data/`, `conf/` | Места для следующих этапов проекта |

В таблице Excel нормировки двух размеров расшифрованы отдельно; во вкладке
`LoRA r16` добавлен второй обязательный расчёт. Числа взяты из `docs/report.json`.

## ДЗ1 сохранено

```sh
make generate
make bench
make check-hw1
```

`make check-hw1` выполняет пять критериев ДЗ1 и небольшие тесты.
Она временно меняет `params.yaml` для проверки другой модели и восстанавливает файл.

Исходный подтверждённый замер ДЗ1: загрузка 1,698473 с, медиана 38,452372 токена/с,
пик RSS 1145,6 МиБ. Это прежний запуск с другими условиями и метрикой памяти.
См. [hardware.md](docs/hardware.md) и `docs/results/hw01-bench.json`.
`make bench` сохраняет свежий временный результат в `docs/bench.json`.

Тема будущего датасета пока не согласована. Для измерений ДЗ2 она не нужна.
Лекции, архивы преподавателя, личные заметки, окружение, веса и записи голоса
в GitHub не включаются.
